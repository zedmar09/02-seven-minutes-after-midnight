# Object Reference Policy

## When An Object Needs A Canonical

Create/reuse an object canonical when a recurring object:
- appears in multiple strips and visual identity matters
- carries a plot clue
- changes state in a precise sequence
- carries exact physical text/markings
- crosses time and must remain recognizable through transformation
- establishes scale/mechanical relationships that later shots must preserve

## Naming — Absolute

Name reusable object references by object identity only, never chapter number.

Examples:
- `cafe-siete-brass-token-canonical-reference-prompt.md`
- `cafe-clock-canonical-reference-prompt.md`
- `daniel-archival-notebook-canonical-reference-prompt.md`

## Authority

Object canonicals control body proportions, construction, handles/edges/spine, materials, neutral state, recurring markings, and approved state vocabulary.

Current strip controls exact current text, temporary damage, food amount, age state, stains, and location.

## Attachment Discipline

Attach an object canonical only when visible or exact design/state matters. Do not attach every reference to every strip.

## Time-Crossing Rule

If an object crosses the service window, the canonical underlying object identity persists through time transformation.

Aging changes material state, not object identity.

Example: same saucer may yellow/craze; it does not become a differently shaped plate. Same paper page may yellow/fade/stain; handwriting layout remains physically derived from the same original page.

## Same-Object Close-Up Rule

A close-up/inset/reference detail never creates a second physical copy in the story world.
